# RBUA Mobile — дизайн-хендофф (для новой сессии: дизайн банерів)

Цей файл — повний контекст того, як ми збирали прототип мобільного банкінгу RBUA (головна, деталі картки/рахунку, профіль, «Послуги»), які вимоги діяли, які стилі, бібліотеки й ресурси використовувались. Новій сесії: прочитай повністю перед роботою.

---

## 1. Проєкт і робочий процес

- **Репозиторій:** `grizhbovskiy/ua-workspace-design`, робоча гілка `claude/cool-hamilton-yqqh6q` (AI-гілки — `claude/...`).
- **Мова інтерфейсу/копірайту:** українська. **Спілкування з користувачем:** російська/українська. **Коміти й коментарі в коді:** англійська.
- **Формат прототипів:** один самодостатній HTML (HTML + CSS + vanilla JS, без фреймворків і збірки), ассети поруч у `assets/`.
  - Головний прототип: `prototypes/home-card/index.html`
  - Сторінка варіантів коммуналки: `prototypes/utility-cards/index.html`
- **Як ділитися:** артефакт-панель у Claude заблокована безпекою користувача → даємо **посилання на коміт** через raw.githack:
  `https://raw.githack.com/grizhbovskiy/ua-workspace-design/<commit-sha>/prototypes/<folder>/index.html`
  (завжди SHA коміту, не гілку — інакше кеш). Після кожної зміни: commit → push → нове посилання + скріншот.
- **Перевірка:** Playwright (Chromium вже встановлений): десктоп 1280×900 + емуляція iPhone 13 / iPhone SE. Скріншоти надсилати користувачу.
- **Пропонування варіантів:** якщо користувач просить «спочатку запропонуй варіанти» — робимо **окрему сторінку з варіантами** (сітка «екранів» + плюси/мінуси + рекомендація), у прототип не вставляємо, доки не обере.

### Обмеження
- **Шрифт Amalia** — локально в `prototypes/home-card/fonts/` (в `.gitignore`), **не пушити** в публічний репо без дозволу. Онлайн-посилання показують системний fallback.
- Не передавати пошту/персональні дані користувача у зовнішні запити.
- PR не створювати без прохання.

### Середовище (cloud)
- Environment `ua-workspace-design` з дозволеними хостами: `www.figma.com`, `mobbin.com`, `upload.wikimedia.org`, `commons.wikimedia.org`.
- Figma MCP: `create_session` → `get_design_context` / `get_screenshot` / `get_metadata`. Ассети з відповіді (`https://www.figma.com/api/mcp/asset/...`) живуть 7 днів — **одразу завантажувати** `curl -L` в `assets/`.
- Для великих фреймів `get_design_context` повертає лише метадані → запитувати дочірні вузли окремо.

## 5. Анімації (motion)

| Easing | Значення | Де |
|---|---|---|
| `--ease` | `cubic-bezier(.2,.8,.2,1)` | загальні переходи |
| `--lift` | `cubic-bezier(.22,1,.36,1)` | підйом картки, шит |
| `--spring` | `cubic-bezier(.32,1.28,.52,1)` | бейджі, пружинки |
| tab pill | `cubic-bezier(.3,1.25,.4,1)` .55s + легке сплющення | таб-бар |

- Тап по картці → картка піднімається (.7s lift), край шита **лишається на місці**; блоки деталей з'являються «цеглинками» знизу вгору (WAAPI, fail-safe 2s).
- Фліп картки до CVV (rotateY 3D), long-press на номері → копіювання.
- Лічильник балансу (tween .7s, ease-out cubic).
- Long-press на аватарі (450ms, vibrate) → bottom sheet профілів; короткий тап → профіль. Працює й мишею.
- Перемикання табів: **екран не рухається**, їде лише індикатор.
- Каруселі: свайп/drag мишею, доводка до слайду, пружинка на краях, точки-індикатор, відступ 16 після останнього слайду.

## 7. Вимоги й уподобання користувача (уроки з ітерацій)

1. **Тільки дизайн-система.** Компоненти, токени, іконки — з UDS/концепту. Якщо чогось немає — питати/брати з Figma, а не вигадувати стиль.
2. **Не ставити ініціали/літери замість логотипів** і не вставляти криві логотипи.
3. **Мінімалізм:** не додавати декоративні іконки, які не несуть інформації (відхилено: іконки послуг у картці коммуналки).
4. **Порожні стани — тієї ж висоти**, що й заповнені, щоб блок не стрибав. Без великих онбординг-карток.
5. **Нічого не «стрибає»:** без зсувів/виїздів екранів при перемиканні табів; край шита фіксований.
6. **Скло помітне:** навбари й таб-бар з виразним блюром, таб-бар не зливається з віджетами (уже за контент).
7. **Відступи по краях** скрізь 16, включно з кінцем каруселі.
8. **Однакова розрядка цифр** на всіх картах/рахунках (без tabular-nums).
9. **Темні/яскраві арти** — затемнення 45% під білий текст (АТБ, Фішка).
10. **Адаптивність:** посилання мають нормально відкриватись на iPhone (safe areas, без фейкового статус-бару, без rubber-band).
11. Коли просять варіанти — показувати окремо й давати рекомендацію; потім робити саме обраний варіант без самодіяльності.
12. Якщо користувач каже «верни як було» — повертати точно, змінюючи лише те, що просили.

## 8. Банери — що взяти в нову сесію

- **Бренд:** жовтий `#FEE600` як акцент (одна головна дія на екрані), темний текст `#2B2D34`, фон `#F8F6F2`, білі поверхні.
- **Шрифт:** Amalia (Bold 700 для заголовків 20–24, Medium 500 для 16, Regular для підписів 12–14).
- **Існуючий шаблон промо-банера** (розділ 4, `.offer`): фіолетовий градієнт `#F2EDFF → #FCF5FF`, бордер `#C3AAFF`, radius 16, ілюстрація 70×70 справа, лінк-CTA 12 Bold Action з шевроном, хрестик закриття.
- **Ілюстрації:** ізометричний стиль UDS (приклад — будинок `1566:225610`); бажано брати з Figma, а не малювати.
- **Розміри:** ширина 358 (390 − 2×16) для банерів на головній; висота від 102. Для каруселі банерів — та ж механіка, що в коммуналці (крок = ширина + 12, точки, відступ 16 в кінці).
- **Тексти:** українською, коротко: заголовок ≤ 2 рядки, CTA одне дієслово («Оформити картку», «Додати адресу», «Сплатити»).
- **Процес:** спершу окрема сторінка з 3–4 варіантами (+/−, рекомендація) → вибір користувача → вбудувати в прототип → коміт + githack-посилання + скріншоти (десктоп і iPhone).
